# Istruzioni Agente

Operi all'interno di un'architettura a 3 livelli che separa le responsabilità per massimizzare l'affidabilità. Gli LLM sono probabilistici, mentre la maggior parte della logica di business è deterministica e richiede coerenza. Questo sistema risolve il problema.

## Architettura a 3 Livelli

**Livello 1: Direttiva (Cosa fare)** — SOP in Markdown in `directives/`. Definiscono obiettivi, input, tool/script, output, casi limite.

**Livello 2: Orchestrazione (Decisioni)** — Il tuo lavoro: leggi le direttive, chiama gli strumenti di esecuzione nell'ordine giusto, gestisci gli errori, aggiorna le direttive con ciò che impari.

**Livello 3: Esecuzione (Fare il lavoro)** — Script Python deterministici in `execution/`. Affidabili, testabili, veloci.

**Perché funziona:** 90% di accuratezza per step = 59% di successo su 5 step. Spingi la complessità in codice deterministico.

## Principi Operativi

1. **Controlla prima i tool esistenti** in `execution/` prima di scrivere nuovi script.
2. **Auto-correggiti** quando qualcosa si rompe: leggi l'errore, correggi, testa, aggiorna la direttiva.
3. **Aggiorna le direttive** mentre impari (sono documenti vivi), ma non crearle/sovrascriverle senza chiedere.

Per piani complessi con subagenti, segui il protocollo in `directives/00-protocollo-subagenti.md`.

Piattaforma SaaS italiana di **tesoreria aziendale**: cash flow/previsioni, riconciliazione bancaria, scadenzario, pagamenti (SEPA, RiBa, SDD, F24), connessione bancaria (PSD2/CBI), reportistica. SPA moderna con API REST (non legacy PHP come Cloud Finance).

### Modalità di accesso

Analisi via **Playwright MCP** (browser automatizzato). Regola fondamentale: abilita SEMPRE il network monitoring PRIMA di navigare. Le API sono la fonte primaria di informazioni.

### Scopo

1. Mappare tutte le funzionalità di tesoreria
2. Ricostruire il modello dati dalle API
3. Documentare logiche di business (riconciliazione, previsioni, matching)
4. Analizzare formati di integrazione (CBI, SEPA XML)
5. Documentare API complete con request/response
6. Identificare regole di validazione
7. Analizzare UI/UX per reimplementazione
8. Mappare verso il gestionale target

Fasi di analisi dettagliate: `directives/00-fasi-analisi.md`

### Istruzioni operative

- Rispondi sempre in **italiano**. Sii analitico, preciso e tecnico.
- Segui il codice effettivo: non fare supposizioni, leggi i file.
- **Non modificare mai alcun dato nell'applicazione** a meno che non venga esplicitamente richiesto.
